# 课标 RAG 质量改进计划书

> 状态：待评审  
> 适用项目：InquiryTeachingPythonService  
> 目标版本：RAG v2  
> 编制日期：2026-09-01

## 1. 背景与结论

当前课标 RAG 已具备本地 BM25、BGE Embedding、Chroma、规则重排、来源展示和检索记录，能够端到端运行，但结果质量仍受以下问题限制：

1. 查询直接拼接“课题、阶段名称、阶段方向、教师输入”，口语噪声和跨学科词会同时进入召回。
2. 课标按固定字符数切块，章节标题、条款层级和表格结构没有成为检索元数据。
3. BM25 使用单字和二元字串，缺少教育领域词组、同义词和字段权重。
4. BM25 与向量分采用单次查询最大值归一化，分布随查询变化，固定权重不稳定。
5. 当前“重排”只是词覆盖率和短语命中率规则，不是真正的 query-passage 相关性模型。
6. 最终结果固定拼接锚点前后各一个 chunk，可能重复，也可能带入无关上下文。
7. 目前缺少标准检索测试集，无法客观判断阈值、权重和模型升级是否真的改善效果。

推荐目标架构：

```text
结构化查询
    ↓
学段/学科/内容类型元数据过滤
    ↓
BM25 Top 40  ─┐
              ├─ RRF 融合 Top 30
向量 Top 40 ──┘
    ↓
Cross-Encoder 重排 Top 20 → Top 6
    ↓
最低相关性判断 / 无结果判断
    ↓
去重、多样性和父级段落扩展
    ↓
按 token 预算打包 Top 4 上下文
```

总体原则是先评测、再改算法；先修数据与召回，再升级模型。

### 1.1 当前系统事实与待测项

下表用于区分“已从代码和数据确认的现状”与“必须在阶段 0 实测的假设”，避免后续计划建立在模糊前提上。

| 项目 | 当前事实或状态 |
|---|---|
| 课标来源 | 当前有数学、物理 2 份来源文档 |
| 数据规模 | 当前数据库约 363 个 chunk；规模会随重新导入变化 |
| chunk 字段 | `id`、`source`、`source_index`、`content`、`created_at`；尚无稳定章节 ID、学科、学段、内容类型和父块字段 |
| 切块 | 按约 512 字符切分，重叠约 64 字符 |
| Embedding | `bge-small-zh-v1.5`，CPU 推理，512 维 |
| 向量库 | Chroma HNSW cosine，当前约 363 条向量 |
| 召回规模 | 向量分支 Top 16；BM25 当前对全部 chunk 计算 |
| 阈值 | 展示和过滤使用原始余弦相似度，当前最低阈值 0.5，但尚未用标注数据校准 |
| 融合 | 向量/BM25 分别按本次查询最大值归一化，再按 0.65/0.35 加权 |
| 重排 | 词覆盖率和短语命中的规则重排，不是 Cross-Encoder |
| 上下文 | 最多 4 个锚点，每个锚点机械补前后各 1 个相邻 chunk |
| 降级 | 向量不可用时回退 BM25 |
| 阶段 0 待测 | 当前 Recall、Precision、串库率、无结果误判率、部署 CPU/RAM、冷/热延迟、并发性能和索引构建时间 |

## 2. 改进目标与验收指标

### 2.1 核心质量指标

| 指标 | 目标 |
|---|---:|
| Recall@20 | 相比当前基线提升至少 10 个百分点，且不低于 90% |
| Precision@4 | 相比当前基线提升至少 15 个百分点 |
| MRR@10 | 相比当前基线提升至少 10% |
| 学科串库率 | 不高于 2% |
| 学段串库率 | 不高于 2% |
| 无关问题误召回率 | 不高于 5% |
| 上下文重复率 | 不高于 10% |
| 来源可追溯率 | 100% |

如果初始基线已经高于目标，则以“不得下降且主要错误样本减少 30%”为验收条件。

指标口径统一如下：

- `Recall@K`：仅对存在正确依据的查询计算；每条查询被 Top K 命中的相关标准段落数 / 全部相关标准段落数，相关度 1 或 2 均算相关，最后按查询宏平均。标准段落使用稳定 `canonical_section_id`，不直接使用可能随切块变化的 chunk ID。
- `Precision@4`：仅对存在正确依据的查询计算；Top 4 中相关度为 1 或 2 的结果数 / 4。返回少于 4 条时，缺少的位置按不相关计，避免通过少返回结果虚增 Precision。
- `MRR@10`：第一个相关度为 2 的结果的倒数名次；不存在则为 0。
- `nDCG@10`：使用 0（不相关）、1（可接受）、2（直接相关）三级标签计算。
- 学科/学段串库率：带显式学科或学段约束的查询中，最终 Top 4 出现冲突结果的查询占比。
- 无关问题误召回率：应返回空结果的查询中，系统仍返回上下文的数量 / 应返回空结果的查询总数。
- 无结果误拒率：存在正确依据的查询中，系统返回空上下文的数量 / 存在正确依据的查询总数；目标不高于 10%。
- 上下文重复率：同时报告去重前重复占比和去重后残留重复率，分母均为对应上下文总 token；“不高于 10%”指去重后残留重复率。
- 来源可追溯率：最终注入的上下文中，可解析到有效来源、章节和稳定段落 ID 的比例。
- 答案正确率：人工按“有证据支持、部分支持、无支持/冲突”三级双人复核；前两级算可接受。所谓“主要错误样本减少 30%”，指“无支持/冲突”的查询数相对基线下降至少 30%。

### 2.2 性能指标

以下目标默认针对“当前部署硬件、热查询、并发 1、当前语料规模”。阶段 0 必须记录 CPU、RAM、操作系统、Python/模型版本和语料规模，并分别测量并发 1/5、冷启动、热查询和连续 100 次查询；若部署环境尚未确定，则这些数值先作为候选目标，不作为发布硬门槛。

| 场景 | P95 目标 |
|---|---:|
| BM25 + 向量召回 | CPU 环境不超过 1.5 秒 |
| 含 Cross-Encoder 重排 | CPU 环境不超过 3 秒；GPU 环境不超过 1 秒 |
| 最终注入上下文 | 默认不超过 4,000 token |

### 2.3 稳定性指标

- 任一新策略均可通过环境变量关闭。
- 向量或重排模型不可用时可降级，但必须记录降级原因。
- 索引版本、模型版本、评分策略版本必须写入检索记录。
- 新旧索引切换失败时可以恢复上一份 Chroma 快照。

## 3. 不同策略的改进方式

### 3.1 查询策略

#### 当前问题

当前把课题、阶段和原始输入全部拼接，容易放大寒暄、任务指令和跨学科示例。例如教师同时提到“力的作用”和“小数/大数”时，数学和物理片段可能一起进入候选。

#### 改进方式

1. 将查询拆成结构化对象：`topic`、`stage_goal`、`user_intent`、`subject`、`education_level`、`content_types`、`keywords`。
2. 去掉“你好、帮我设计、你认为”等低信息口语。
3. 学科和学段优先使用会话显式字段；关键词识别只作为补充。
4. 对短查询为 BGE v1.5 增加检索指令，并通过评测决定是否启用。BGE 官方建议短查询检索长文档时对 query 加指令，而 passage 不加。[BGE small zh v1.5 模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)
5. 仅在首轮召回置信度不足时启用 LLM 多查询扩展，生成“概念查询、课标能力查询、教学活动查询”三种表达；正常查询不增加 LLM 调用。

#### 不建议立即采用

- 不先上全量 HyDE。课标场景中生成式假文档容易把通用教学话术带入召回。
- 不用 LLM 直接决定最终命中文档；LLM 只做查询改写，结果仍由可评测检索链决定。

### 3.2 文档解析与切块策略

#### 当前问题

固定 512 字符切块会截断条款层级；表格被压平成文本后容易形成大量数字噪声；最终依赖相邻 chunk 补上下文，重复率较高。

#### 改进方式

1. 使用 tokenizer 计数，目标子块 320～480 token，重叠 48～64 token。
2. 识别标题、章节、条款编号、学段、学科、课程目标、内容要求、教学提示、学业要求和评价建议。
3. 建立父子块：
   - 子块用于召回，建议 200～350 token；
   - 父块用于最终上下文，建议 700～1,200 token；
   - 命中子块后扩展到对应父块，而不是机械拼接前后 chunk。
4. 表格按“表名 + 表头 + 当前行”生成独立块；连续纯数字行不直接参与普通正文召回。
5. 为每个块保存 `section_path`、`page`、`subject`、`education_level`、`content_type`、`parent_id`。
6. 对 PDF/DOCX 提取结果增加质量检查：空页、重复页眉页脚、乱码比例、数字比例和超短块比例。

### 3.3 BM25 策略

#### 当前问题

单字和二元字串召回率尚可，但容易受到常见汉字影响，且没有标题、章节和正文的差异化权重。

#### 改进方式

1. 保留当前字粒度作为兜底，同时增加教育领域词典分词。
2. 建立领域同义词：如“科学探究/实验探究”“评价/学业质量”“猜想/假设”“证据/数据记录”。
3. 对字段加权：标题和章节路径权重大于正文，来源文件名只用于过滤，不参与正文得分放大。
4. BM25 独立召回 Top 40，不再先和向量分做最大值归一化。
5. BM25 原始分继续用于观测，排序融合使用名次而不是不可跨查询比较的绝对值。
6. 课标规模扩大后将 BM25 倒排索引化，避免每次遍历全部 chunk。

### 3.4 向量检索策略

#### 当前问题

当前模型可用，但 query 没有检索指令；Top 16 候选较少；固定 0.5 阈值尚未经过数据校准。BGE 官方也明确提示，单纯“大于 0.5”不能代表语义相似，阈值应按业务数据分布选择。[BGE v1.5 阈值说明](https://huggingface.co/BAAI/bge-small-zh)

#### 改进方式

1. 第一阶段继续使用 `bge-small-zh-v1.5`，避免同时更换模型和算法。
2. 向量独立召回 Top 40，再应用经评测校准的阈值。
3. 分学科统计正例和负例余弦分布，不强制所有学科共用同一阈值。
4. 阈值只控制向量召回分支，不永久阻断高质量 BM25 精确匹配；最终是否返回由重排分和无结果判断共同决定。
5. 对模型目录、维度、query instruction、索引版本建立完整签名，任一变化都要求重建索引。
6. 若 v1.5 在长条款或跨语言材料上仍明显不足，再 A/B 测试 BGE-M3。BGE-M3 支持 dense、sparse、multi-vector 三种能力，维度 1024、最长 8192 token，但资源占用和重建成本明显更高。[BGE-M3 官方模型说明](https://huggingface.co/BAAI/bge-m3)

### 3.5 混合融合策略

#### 当前问题

当前向量和 BM25 都除以本轮最高分，再按 0.65/0.35 加权。该方法对候选分布敏感：本轮最好结果即使质量一般，也会得到 1.0 的相对分。

#### 改进方式

采用 Reciprocal Rank Fusion（RRF）：

```text
RRF(d) = Σ 1 / (k + rank_i(d))
```

- 初始使用 `k=60`。
- BM25 Top 40 和向量 Top 40 独立排序。
- 按 RRF 合并为 Top 30。
- 不依赖不同评分体系的数值尺度。
- 原始 BM25、余弦、各路名次和 RRF 分全部保留，便于解释。

只有在评测集证明线性加权优于 RRF 时，才保留可学习或人工权重融合。

### 3.6 重排策略

#### 当前问题

当前重排只计算词覆盖率和完整短语命中率，无法判断“查询和段落是否真正回答同一个教学问题”。

#### 改进方式

1. RRF Top 30 中取前 20 条送入 Cross-Encoder。
2. 第一选择：CPU 环境先评测 `bge-reranker-base`；GPU 或可接受更高内存时评测 `bge-reranker-v2-m3`。
3. Cross-Encoder 直接对 query-passage 对输出相关性分数，然后选 Top 6。
4. 最终 Top 4 仍保留学科、学段和来源多样性规则。
5. Reranker 不可用时降级到 RRF + 规则重排。

BGE 官方说明建议先用轻量检索召回较大候选集，再用 Cross-Encoder 重排得到最终少量结果；`bge-reranker-v2-m3` 可输出 query-passage 相关性并通过 sigmoid 映射到 0～1，但模型文件约 2.29 GB，需要单独评估部署资源。[BGE Reranker 官方说明](https://huggingface.co/BAAI/bge-reranker-v2-m3/blob/main/README.md)

### 3.7 无结果判断策略

#### 当前问题

只要候选集非空，当前流程通常都会返回 Top 4；而固定余弦阈值 0.5 只能约束向量分支，不能识别“BM25 碰巧命中常见词但问题与课标无关”的情况。RRF 分又是名次融合分，不能直接作为跨查询通用阈值。

#### 改进方式

1. 新建 `RetrievalDecisionService`，统一输出 `accepted`、`no_result` 或 `retrieval_unavailable`，不把判断散落在各召回分支。
2. 阶段 3 采用可解释的规则树，不引入分类器。每个候选计算：最高余弦、BM25 在本语料中的经验分位数、关键词覆盖率、是否被双路同时命中、RRF Top 1/Top 2 间隔及元数据一致性。
3. 阶段 3 的决策顺序固定为：
   1. BM25 和向量同时不可用：返回 `retrieval_unavailable`，不注入上下文；
   2. 可用分支均无候选，或所有候选与显式学科/学段冲突：返回 `no_result`；
   3. Top 1 被双路命中，且余弦或 BM25 分位数达到普通阈值，同时关键词覆盖达到普通阈值：接受；
   4. 仅一个分支有候选时，必须同时达到该分支的高阈值和最低关键词覆盖阈值才接受；向量候选全被过滤时走 BM25 单路规则，反之亦然；
   5. 其余情况返回 `no_result`。只有 1 条候选时不计算名次间隔，按单路/双路命中规则判断。
4. 阶段 4 在阶段 3 候选通过后增加 Reranker 闸门：Top 1 分达到阈值，且候选不少于 2 条时 Top 1/Top 2 间隔也达到阈值；只有 1 条候选时仅使用更严格的 Top 1 阈值。
5. 所有“普通阈值”“高阈值”和 Reranker 阈值都在验证集网格搜索；先满足无关问题误召回率 ≤ 5% 和无结果误拒率 ≤ 10%，再在合格组合中最大化 `F0.5`，使 Precision 优先于 Recall。冻结测试集只验收，不参与选阈值。
6. Reranker 不可用时退回阶段 3 的规则树，不能只用 RRF 绝对分判断；RRF 不启用时忽略“双路 RRF 间隔”特征，其余规则仍可运行并记录降级。
7. 每次拒绝记录 `no_result_reason`；传给主模型时明确写入“未检索到可靠课标依据”。`retrieval_unavailable` 必须作为服务故障记录，不能统计成正常无结果。
8. 使用 `CURRICULUM_NO_RESULT_MODE=off|rule|reranker` 独立控制，便于 shadow 观察和快速回滚。

### 3.8 最终拼接策略

#### 当前问题

固定拼接锚点前后各一个 chunk，可能重复、跨章节或把表格噪声带入模型。

#### 改进方式

1. 重排完成后再扩展上下文，禁止在重排前拼接邻居。
2. 优先扩展到父级条款；没有父块时才使用相邻 chunk。
3. 相邻扩展必须满足同一来源、同一章节路径且索引连续。
4. 使用 chunk ID 集合去重；再用文本相似度去除近重复段落。
5. 默认最多 4 个结果、2 个来源，每个来源最多 2 个结果。
6. 按相关性顺序打包，默认 RAG 预算 4,000 token；超限时优先保留命中句及其标题。
7. 在上下文中携带来源、章节路径、页码和片段 ID，回答只展示简短来源。

### 3.9 反馈与观测策略

1. 扩展 `rag_records`：记录模型版本、索引版本、阈值版本、各路 Top K、过滤原因、耗时和最终 token 数。
2. 管理页面展示完整流水线：原始候选 → 过滤 → RRF → Reranker → 最终上下文。
3. 增加管理员反馈：相关、不相关、学科错误、学段错误、缺少关键片段。
4. 每周自动汇总低分、高争议和无结果查询，进入评测集。
5. 严禁直接用线上点击作为唯一标签；人工确认后才进入正式测试集。

## 4. 分步实施计划

### 阶段 0：建立评测基线

**目标：** 先回答“当前到底差在哪里”，避免凭个别截图调整全局参数。

#### 实现步骤

1. 新建 `tests/fixtures/rag_eval.jsonl`，先定义并校验 JSON Schema。
2. 以“源文档版本 + 规范化章节路径 + 条款编号/内容 hash”建立独立于 chunk 的标准条款表和 `canonical_section_id`；评测标签指向该 ID，不直接绑定 v1/v2 chunk ID。
3. 建立 v1 chunk 到标准条款的多对多映射；一个 chunk 跨越多个条款时记录每个条款的字符重叠范围，命中任一被标为相关的标准条款即可判为相关，不能只按“主条款”吞掉边界信息。
4. 初始收集不少于 600 条查询，其中存在正确依据和应返回空结果各不少于 300 条；每个当前语料覆盖的主要学科至少 100 条、每个适用学段至少 60 条、跨学科至少 60 条。当前语料不覆盖的学科或学段标为“域外查询”，不能伪造正例。
5. 每条数据标注：期望来源、稳定条款 ID、0/1/2 相关度、证据点、禁止学科/学段、是否应返回空结果。
6. 至少 20% 样本由两人独立标注，分歧由第三人仲裁；计算加权 Cohen's kappa。
7. 对正例/空结果、学科、学段和查询类型做分层后，按 60%/20%/20% 分为开发集、阈值验证集和冻结测试集；验证集与冻结测试集各至少包含 60 条空结果查询。开发期间不得依据冻结测试集调参。
8. 新建 `scripts/evaluate_curriculum_rag.py`，固定随机种子、索引版本和策略版本。
9. 输出 Recall@K、Precision@4、MRR、nDCG、串库率、误召回率、误拒率、答案证据支持率及 P50/P95 延迟，并为比例指标输出 Wilson 95% 置信区间。
10. 保存当前策略基线报告和运行环境快照，不修改任何线上排序参数。

#### 验收与回滚

- 数据集至少 600 条，并满足上述分层最低样本量；当前语料范围内的学科均有正例覆盖。
- 双标样本加权 kappa 不低于 0.70；未达标先统一标注准则再重标。
- 同一索引重复执行结果一致。
- 本阶段只增加测试工具，无线上行为变化，无需业务回滚。

#### 预计工作量

开发 5～8 人日，标注与仲裁 4～6 人日；合计 9～14 人日。

### 阶段 1：查询清洗与会话显式元数据

**目标：** 优先解决数学/物理串库和口语噪声。

#### 实现步骤

1. 给会话增加显式 `subject`、`education_level` 字段；旧会话允许为空。
2. 实现 `CurriculumQuery` 结构体，分离检索文本与过滤字段。
3. 加入轻量口语清洗和关键词提取。
4. 显式字段优先于关键词推断；两者冲突时保留显式字段并记录冲突，旧会话字段为空时才推断。
5. 由于 v1 chunk 尚无结构化 metadata，本阶段先基于现有 `source` 和内容规则做召回后的兼容性过滤；真正的召回前 metadata 过滤在阶段 2 完成。
6. A/B 测试 BGE query instruction，分为无指令、官方中文指令、业务短指令三组。
7. 分别保留查询 v2、query instruction、会话元数据过滤开关，便于隔离收益和回滚。

#### 验收与回滚

- 学科串库率降低到 2% 以下。
- Recall@20 不得下降超过 2 个百分点。
- 关闭开关即可恢复当前查询拼接方式。

#### 预计工作量

开发 5～7 人日。

### 阶段 2：结构化切块、块元数据与索引迁移

**目标：** 让召回单元与课标条款语义边界一致。

#### 实现步骤

1. 数据库增加稳定条款 ID、章节、页码、学科、学段、内容类型、父块 ID 和索引版本字段；新字段先允许为空，保证旧数据可读。
2. 实现 token-aware 子块与父块生成。
3. 单独处理表格和纯数字内容。
4. 在 BM25 与 Chroma 两路召回前实现 `subject`、`education_level`、`content_type` 预过滤；字段为空时按兼容规则处理并记录。
5. 建立 `curriculum_chunks_v2` 临时索引，不覆盖现有索引。
6. 校验数据库/向量条数、内容 checksum、向量维度、随机内容抽样和父子关系完整性。
7. 建立 v2 chunk 到阶段 0 标准条款表的多对多映射，验证同一原文条款在 v1/v2 下的 `canonical_section_id` 一致。
8. 对 v1/v2 同一评测集做对照。
9. 达标后通过索引指针原子切换，并保留最近一份 v1 快照。

#### 验收与回滚

- 关键条款截断率低于 2%。
- Precision@4 至少提升 5 个百分点。
- Recall@20 不得下降超过 2 个百分点，无结果误拒率不高于 10%。
- 表格噪声误召回减少 50%。
- 切回索引版本即可回滚。

#### 预计工作量

开发 6～9 人日。

### 阶段 3：双路召回、RRF 融合与初步无结果判断

**目标：** 消除单次最大值归一化的不稳定性，提高精确词和语义召回的互补性。

#### 实现步骤

1. BM25 和向量分别召回 Top 40。
2. 余弦阈值只过滤向量分支，并通过评测数据校准，不直接假设 0.5 最优。
3. 实现 RRF，初始 `k=60`，合并 Top 30。
4. 保存各路名次、原始分和 RRF 分。
5. 实现 `RetrievalDecisionService` 的第一版，使用最高余弦、BM25 分位数、覆盖率、RRF 名次间隔和元数据一致性判断是否返回空结果。
6. 在验证集校准决策阈值，并单独报告误召回率和误拒率。
7. 将现有 0.65/0.35 融合作为可回滚旧策略。
8. 增加 `CURRICULUM_FUSION_MODE=weighted|rrf` 和独立无结果判断开关。

#### 验收与回滚

- Recall@20 相比基线提升至少 8 个百分点，且 Precision@4 不得下降超过 2 个百分点。
- 无关问题误召回率不得上升，无结果误拒率不高于 10%。
- 切换 `CURRICULUM_FUSION_MODE=weighted` 即可回滚。

#### 预计工作量

开发 4～6 人日。

### 阶段 4：Cross-Encoder 重排与最终无结果判断

**目标：** 提高最终 Top 4 的真实相关性。

#### 实现步骤

1. 实现独立 `CurriculumRerankerService`，支持模型缓存、批处理和超时。
2. 对 RRF Top 20 进行 query-passage 打分。
3. 在 CPU 上评测 `bge-reranker-base`；资源允许时再评测 `bge-reranker-v2-m3`。
4. 通过评测集确定 reranker 阈值和 Top K。
5. 将 Reranker Top 1 分数及 Top 1/Top 2 间隔接入 `RetrievalDecisionService`，完成最终无结果判断。
6. 超时或加载失败时自动使用阶段 3 的 RRF 排序和初步决策特征。
7. 增加 `CURRICULUM_CROSS_ENCODER_ENABLED` 和性能监控。

#### 验收与回滚

- 相比原始基线，Recall@20 累计提升至少 10 个百分点且 Precision@4 累计提升至少 15 个百分点；若基线已较高，则使用 2.1 节替代条件。
- 无关问题误召回率不高于 5%，无结果误拒率不高于 10%。
- P95 满足性能目标。
- 关闭 Cross-Encoder 后恢复阶段 3 的可用能力；回滚保证服务可用，不承诺排序质量完全等价。

#### 预计工作量

开发 5～8 人日，不含模型下载时间。

### 阶段 5：上下文打包与去重

**目标：** 减少重复和噪声，让主模型看到更短、更完整的证据。

#### 实现步骤

1. 改为“重排后父块扩展”，取消无条件前后邻居拼接。
2. 实现 chunk ID 去重和近重复文本去重。
3. 加入章节边界检查、来源配额和 token 预算。
4. 上下文输出增加章节路径、页码和片段 ID。
5. 记录注入前后的 chunk 数、字符数、token 数和重复率。
6. 对答案的来源引用正确率进行人工抽样。

#### 验收与回滚

- 上下文重复率不高于 10%。
- 平均 RAG token 数减少至少 20%，答案正确率不得下降。
- 可切回 `neighbor` 拼接模式。

#### 预计工作量

开发 3～5 人日。

### 阶段 6：可选模型与查询增强 A/B

**目标：** 只在前述架构稳定后判断是否需要增加模型成本。

#### 实现步骤

1. 用同一评测集比较 `bge-small-zh-v1.5` 与 BGE-M3 dense。
2. 比较索引大小、构建时间、CPU/GPU 内存、P95 延迟和质量提升。
3. 仅当 Recall@20 或 Precision@4 至少提升 5 个百分点，同时满足既定 P95 和内存上限时才迁移 Embedding 模型。
4. 将“低置信度”定义为无结果决策阈值附近的灰区；只对灰区查询试验 LLM 多查询扩展，限制最多生成 3 个查询。
5. 对 LLM 扩展记录额外 token 成本和延迟。
6. 不达标则保持当前 Embedding，不把模型升级作为项目完成条件。

#### 验收与回滚

- 模型升级必须满足质量收益大于资源成本的评审结论。
- 所有索引按模型名称和版本隔离，可以直接切回。

#### 预计工作量

开发 4～7 人日。

### 阶段 7：灰度发布与持续迭代

**目标：** 建立可重复使用的实验分流、监控与自动回滚能力，再逐步放量 RAG v2。

#### 实现步骤

1. 实现稳定实验分桶：按用户/会话 hash 固定进入 control 或 treatment，记录 `experiment_id`、策略版本和分桶原因。
2. 实现 shadow 双跑：旧策略正常响应，新策略异步执行并单独记录；设定超时和采样率，shadow 失败不得拖慢线上响应。
3. 实现监控聚合：按滚动窗口计算有效检索数、人工反馈、串库率、误召回率、误拒率、P50/P95、模型失败率和接口错误率。
4. 实现管理员反馈入口、告警通知链路和发布控制器；自动切回动作必须幂等并写审计日志，同时允许人工锁定旧策略。
5. 先完成故障演练：模拟模型加载失败、指标越线、通知失败和回滚重复执行，确认降级与告警可用。
6. 新策略先以 shadow 模式运行，只记录结果，不注入主模型。
7. 对管理员或指定用户开放 10% 灰度；每一档至少积累 200 次有效检索且观察不少于 2 个工作日。
8. 比较旧策略与新策略的人工反馈、检索指标、延迟和错误率，再逐步扩大到 50%、100%。
9. 连续一周稳定后把 v2 设置为默认；旧策略至少保留一个发布周期。
10. 每月从真实失败查询中补充评测集并重新校准阈值。

#### 验收与回滚

- 线上学科串库、空结果、模型加载失败和延迟均在目标范围。
- 发布控制器按滚动 24 小时窗口监控；样本少于 100 次只告警不自动判定，达到 100 次后，学科/学段串库率、误召回率、P95 或错误率任一相对旧策略恶化超过 20%，自动切回旧策略并通知管理员。

#### 预计工作量

若需从零建设上述能力，开发 7～11 人日，另需至少一周日历观察期；若已有通用发布与监控基础设施，可缩短为 3～5 人日。

## 5. 推荐实施顺序与里程碑

| 里程碑 | 包含阶段 | 预期收益 | 累计工作量 |
|---|---|---|---:|
| M1：结果可衡量 | 阶段 0 | 建立客观基线 | 9～14 人日 |
| M2：减少串库 | 阶段 1～2 | 查询更干净、条款更完整 | 20～30 人日 |
| M3：排序质量提升 | 阶段 3～4 | Top 4 相关性显著提高 | 29～44 人日 |
| M4：上下文质量提升 | 阶段 5 | 更少重复、更低 token | 32～49 人日 |
| M5：可选能力升级 | 阶段 6～7 | 模型 A/B、灰度上线 | 43～67 人日 |

推荐先完成 M1～M3。通常结构化过滤、RRF 和 Cross-Encoder 已能解决大多数当前问题；是否升级到 BGE-M3，应由评测结果决定。

以上均为人日估算：阶段 0 包含独立标注与仲裁人日，阶段 7 的累计值按“从零建设发布基础设施”的 7～11 人日计算，但不包含至少一周的日历观察时间。多人并行会缩短日历时间，不会等比例减少总人日。

## 6. 配置项规划

建议新增：

```text
CURRICULUM_QUERY_V2_ENABLED=false
CURRICULUM_QUERY_INSTRUCTION_ENABLED=false
CURRICULUM_METADATA_FILTER_ENABLED=false
CURRICULUM_FUSION_MODE=weighted
CURRICULUM_BM25_TOP_K=40
CURRICULUM_VECTOR_TOP_K=40
CURRICULUM_RRF_K=60
CURRICULUM_RERANK_TOP_K=20
CURRICULUM_NO_RESULT_MODE=off
CURRICULUM_CROSS_ENCODER_ENABLED=false
CURRICULUM_CROSS_ENCODER_MODEL=BAAI/bge-reranker-base
CURRICULUM_CONTEXT_PACKING_MODE=neighbor
CURRICULUM_CONTEXT_TOKEN_BUDGET=4000
CURRICULUM_INDEX_VERSION=v1
```

所有新功能默认关闭，逐阶段完成验收后再更改默认值。

配置依赖和降级规则：

- `CURRICULUM_METADATA_FILTER_ENABLED=true` 且使用 v1 索引时，只启用阶段 1 的召回后兼容过滤；使用 v2 索引时才启用召回前 metadata 过滤。
- `CURRICULUM_CONTEXT_PACKING_MODE=parent` 依赖 v2 的 `parent_id`；配合 v1 索引属于非法组合，启动校验应拒绝或自动回退 `neighbor` 并告警。
- `CURRICULUM_NO_RESULT_MODE=rule` 使用阶段 3 规则树；`reranker` 依赖 Cross-Encoder，模型关闭、超时或不可用时自动退回 `rule`。
- `CURRICULUM_FUSION_MODE=weighted` 时无 RRF 间隔特征，决策服务忽略该特征并记录 `decision_degraded_reason=fusion_without_rrf`。
- Cross-Encoder 可独立关闭；关闭后检索和无结果判断必须仍能走阶段 3 路径。
- 所有自动降级都必须写入检索记录，不能静默改变评分语义。

## 7. 测试计划

每阶段必须包含：

1. 单元测试：分词、过滤、阈值、RRF、重排、去重和预算截断。
2. 集成测试：上传课标、重建索引、聊天检索、记录保存和降级路径。
3. 离线评测：固定测试集全量运行并生成 JSON/Markdown 报告。
4. 回归测试：现有 FastAPI 测试和前端构建全部通过。
5. 性能测试：冷启动、热查询、并发查询、模型加载和内存峰值。
6. 人工测试：至少检查 20 个跨学科或容易串库的真实问题。

禁止只凭单个查询结果调整全局权重或阈值。

## 8. 主要风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 评测集偏向少数学科 | 分层采样，按学科和学段分别报告指标 |
| Cross-Encoder 在 CPU 上过慢 | 限制 Top 20、批处理、超时降级；先评测 base 模型 |
| 新切块导致索引和数据库不一致 | 版本化双索引、校验 checksum、原子切换 |
| 阈值导致正确结果被全部过滤 | 评测校准、按学科分布设置、保留可解释的无结果状态 |
| 多查询增加成本和噪声 | 只在低置信度时启用，最多 3 个查询 |
| 上下文压缩损失必要条款 | 父块扩展、标题和命中句优先、人工抽样 |
| 历史检索记录分数语义变化 | 增加 `scoring_version`，前端按版本解释字段 |

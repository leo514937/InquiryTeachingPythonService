## 一、项目与开发环境

项目名称：`InquiryTeachingPythonService`

当前目标分支：`ads`

HTML 原型位置：项目根目录下的 `todo/` 文件夹。

参考文件预计为：

`todo/inquiry_workspace_dag_prototype.html`

请先检查当前 Git 分支、项目目录和 HTML 文件的实际路径。

如果当前不在 `ads` 分支，不要直接修改其他分支的代码。先检查工作区是否存在未提交的修改，并在确保不会覆盖已有工作的情况下切换至 `ads` 分支。

如果 HTML 文件名称不同，请搜索 `todo/` 文件夹中的 HTML 文件，确认正确原型后再继续。

**必须完整阅读 HTML 原型的 HTML、CSS 和 JavaScript，理解其中的布局、视觉设计、动画以及交互状态。不能只根据截图或文件名称进行重构。**

## 二、任务目标

当前项目已经新增 Inquiry Workspace 模块，具备 Orchestrator Agent、原子能力、DAG 编排、教学对象管理、实验组件和报告生成等功能。

但当前前端主要采用传统后台管理系统式布局，缺乏 AI 原生产品应有的视觉体验。

本次要求：

**以 `todo/` 下的 HTML 为设计基准，重构 Inquiry Workspace 前端，实现浅色专业工作台 + 实时动态 DAG 编排 + 教学成果可视化的完整交互体验。**

用户点击“发送 / 开始生成”后，应该能够直观地看到：

1. AI 接收并分析教学需求。
2. Planner 构建本次任务的 DAG。
3. 节点逐步出现，自动建立依赖连线。
4. Scheduler 根据 DAG 依赖执行节点。
5. 节点状态实时变化，并展示执行动画。
6. 多个独立节点可以同时执行。
7. 节点完成后展示对应的教学成果。
8. 所有节点完成后展示最终教学工作空间。
9. 用户可以切换查看完整教学设计报告。
10. 可以随时重新查看历史 DAG 及执行详情。

重点是将 HTML 中的演示效果转化为**真实、可运行、可交互、可恢复的 Vue 前端功能**。

## 三、最高优先级：非破坏性重构

此次重构仅针对新增的 Inquiry Workspace 前端。

必须遵守：

1. 不删除、不替换原有对话式教学模式。
2. 不删除原有主导师 Agent、领域专家 Agent 和固定教学阶段工作流。
3. 不破坏已有知识库、RAG、专家授权和知识图谱机制。
4. 不删除 Inquiry Workspace 现有功能。
5. 不修改现有 Orchestrator 的核心规划逻辑。
6. 不修改原子能力注册及调用语义。
7. 不改变 Scheduler 的执行机制。
8. 不删除原有教学对象编辑、局部重编排、报告导出和实验交互能力。
9. 不进行破坏性数据库迁移。
10. 不因为前端重构而改变后端 API 的已有语义。

如果发现现有接口无法满足新 UI，可新增兼容性接口或字段，但应尽量避免大规模修改后端。

**本次重构的本质是更换 Inquiry Workspace 的前端呈现和交互组织，不是重新实现已有业务能力。**

## 五、重构整体页面架构

建议采用稳定的 Workspace Shell，保持顶部、侧边导航以及空间状态一致。

### 5.1 左侧导航栏

按照 HTML 原型实现。

应包含：

- Inquiry Studio 标识
- 新建教学工作空间
- Agent 编排
- 教学画布
- 教学报告
- 最近工作空间
- 返回原有对话工作台

导航应有明确的选中态和悬停效果。

支持折叠，避免占用过多的中央空间。

### 5.2 顶部工作空间工具栏

包含：

- 当前教学主题
- 工作空间名称
- 当前运行状态
- 保存状态
- 运行历史入口
- 报告入口
- 主要操作按钮

在 DAG 执行、教学画布和报告之间切换时，顶部工作空间框架应保持稳定。

### 5.3 中央主区域

中央区域是核心，需要支持三种主要视图：

**A. Agent DAG 编排视图**

动态展示真实 Planner 生成的 DAG。

**B. 教学工作空间视图**

展示 Agent 生成的结构化教学对象，支持编辑、查看和局部重新生成。

**C. 报告视图**

展示根据当前教学对象统一生成的完整教学设计报告，支持原有预览和导出功能。

### 5.4 右侧面板

根据当前状态动态展示：

- Agent 执行摘要
- 节点详情
- 实时事件
- 教学对象属性
- 来源证据
- 错误信息
- 局部重编排结果

不应该在同一个面板中无序堆叠所有功能。

## 六、重点功能：动态 DAG 自动搭建

这是本次重构的最高优先级功能。

### 6.1 用户点击发送后的行为

当教师输入：

“设计一节初中物理光的反射探究课，45 分钟，包含教学目标、探究问题、实验活动和学习评价。”

前端执行以下交互：

**阶段 1：任务提交**

- 输入框进入提交状态。
- 创建或使用现有 Workspace。
- 调用真实 Run API。
- 展示任务已接收的状态。
- 自动切换到 DAG 编排视图。

**阶段 2：Agent 规划**

- 展示 Planner 正在分析需求。
- 展示当前任务目标。
- 等待真实计划结果。
- 不预先绘制固定九节点模板。

**阶段 3：DAG 构建**

当后端返回真实 DAG：

- 从 Plan JSON 读取节点。
- 读取 Capability ID。
- 读取节点输入。
- 读取 `depends_on`。
- 自动计算节点层级。
- 自动绘制依赖连线。
- 通过 stagger 动画展示节点入场。
- 保持动画流畅，不要让节点突然全部堆叠在一起。

需要特别注意：

**DAG 节点必须来自真实 Planner 结果，不能使用 HTML 原型中的模拟节点列表作为生产数据。**

### 6.2 DAG 渲染方案

优先评估 Vue Flow + Dagre。

要求：

- 支持自动布局。
- 支持缩放。
- 支持画布平移。
- 支持适应屏幕。
- 支持自定义节点。
- 支持不同任务生成不同拓扑。
- 支持并行节点分支。
- 支持节点详情交互。
- 支持最多 30 个节点的清晰展示。

优先采用由上到下的层级布局。

节点位置不应因为执行状态更新而频繁发生变化。

### 6.3 节点状态

至少支持：

| 状态 | 视觉表现 |
|---|---|
| Pending | 灰色，等待执行 |
| Ready | 淡绿色，准备执行 |
| Running | 品牌绿色高亮，柔和脉冲 |
| Succeeded | 绿色完成图标 |
| Failed | 红色错误状态 |
| Retrying | 橙色重试标记 |
| Waiting Review | 黄色审核状态 |
| Cancelled | 灰色取消状态 |
| Skipped | 弱化显示 |

每种状态必须使用后端真实状态映射。

不得基于前端计时器伪造任务执行状态。

### 6.4 连线动画

参考 HTML 原型实现：

- 节点依赖连接线。
- 连线进入动画。
- 当前执行路径高亮。
- Running Edge 轻量流动效果。
- 已完成路径的颜色变化。
- 并行分支同时高亮。

对于动画，应优先使用 CSS 或 SVG。

避免引入性能成本较高的复杂动画框架。

### 6.5 节点点击交互

点击节点，在右侧展示真实执行信息：

- 节点 ID
- Capability ID
- Capability 版本
- 当前状态
- 前置依赖
- 输入摘要
- 输出摘要
- 生成教学对象
- 执行耗时
- 重试次数
- 错误原因
- 检索证据

需要遵守现有权限控制，不能将未经授权的知识库内容直接展示在节点详情中。

## 七、真实 Runtime 与 SSE 集成

HTML 原型中的 JavaScript 可能采用模拟事件、延时函数和演示数据。

重构时必须严格区分：

**展示动画可以复用，但模拟业务逻辑不能进入生产环境。**

请审计现有：

- Planner
- Runtime Scheduler
- Workspace Run API
- Run Nodes API
- Workspace Events
- SSE 订阅接口

要求：

1. 运行开始后读取真实 Run ID。
2. 获取当前运行的完整 DAG 快照。
3. 订阅真实 SSE 运行事件。
4. 按 node_id 更新节点状态。
5. 支持事件序号和去重。
6. 支持断线重连。
7. 支持浏览器刷新后恢复节点状态。
8. 支持查看历史 DAG。
9. 支持取消任务。
10. 支持执行失败和审核暂停状态。

特别注意：

**Planner、Scheduler 和前端 DAG 的状态必须保持一致。**

不能出现后端运行失败，但前端仍显示全部成功的情况。

教师应能够：

- 查看教学目标。
- 查看课标依据。
- 查看探究问题。
- 查看实验活动。
- 查看评价任务。
- 修改教学对象。
- 触发局部重编排。
- 查看对象版本。

- 查看完整报告。

必须复用现有 Workspace Artifact API。

不允许将真实教学对象替换为 HTML 演示中的静态内容。

### 局部重编排的 DAG 展示

当教师修改实验条件后：

1. 调用现有局部重编排 API。
2. 获取本次新的 Run ID。
3. 展示本次真实生成的局部 DAG。
4. 高亮本次需要重新执行的能力节点。
5. 不影响未变化的教学对象。
6. 执行完成后更新相关对象。
7. 同步刷新报告预览。

如果后端没有提供完整的影响范围数据，应明确提示，不得伪造“仅修改三个节点”等结论。

## 十四、验收标准

至少验证以下真实场景。

### 场景 A：完整教学设计

用户输入完整教学需求。

预期：

- 自动创建 Workspace。
- 生成真实 DAG。
- 节点自动布局。
- 执行状态实时更新。
- 生成真实教学对象。
- 完成后进入教学画布。
- 可以查看和导出报告。

### 场景 B：仅生成实验

用户只要求设计一个实验。

预期：

- Planner 根据需求选择能力。
- DAG 不应强制包含所有九类节点。
- 节点数量和依赖由真实后端决定。
- 最终展示相关实验对象。

### 场景 C：局部重编排

用户修改已有实验。

预期：

- 生成新的局部运行。
- 展示实际受影响节点。
- 运行后更新对应 Artifact。
- 不覆盖无关教学对象。
- 报告同步更新。

### 场景 D：异常恢复

执行过程中刷新页面、断开网络或发生节点失败。

预期：

- DAG 能从真实数据恢复。
- 不重复启动任务。
- 状态不会回退。
- 错误信息能够正确展示。

### 场景 E：原有模块回归

必须确认：

- 原有对话模式正常。
- 原有固定教学阶段正常。
- 主导师与领域专家正常。
- 知识库授权正常。
- 旧草案、知识图谱和导出正常。
- 新旧两种工作形态可以独立使用。
